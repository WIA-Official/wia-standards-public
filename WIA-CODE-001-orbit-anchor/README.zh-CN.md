## 为什么要做另一种二维码？

QR 码之所以是主流，靠的是普及度，而非性能。它被标准化为仅黑白二值（ISO/IEC 18004），
其方形定位图案依靠直线扫描来读取，这在透视倾斜、运动和弱光条件下会明显劣化——而这些
恰恰正是眼镜设备、移动摄像头和现场/灾害场景的典型条件。WIA-CODE 依靠**圆形与圆心**而
非直线来读取，由此获得三项结构性优势：旋转不变性、由单个靶心图案即可闭式求解的透视
恢复能力，以及积分式（噪声平均化）检测。

## 它是什么

- **轨道锚点定位（Orbit anchor localization）**——由中心同心圆*靶心*（核心）+ 四个角部
  *卫星点*（其中一个为环形"北极星"用于确定旋转方向）+ 一个格式轨道环组成。通过 Fast
  Radial Symmetry Transform 检测，再精化为亚像素级单应性变换（homography）；当视角过陡
  导致卫星点被压缩时，可仅凭核心图案通过**圆锥束（conic-pencil）透视恢复**完成定位。
- **数据层**——负载数据 → 帧（header + CRC16）→ Reed–Solomon 纠错 → 数据单元格。
  独立实现的 Reed–Solomon/CRC 编解码器（`rs.js`）——无需外部引擎。
- **多级容量**——每个数据单元格可携带 1、2 或 3 个比特（对应 2/4/8 级灰度），从而成倍
  提升容量。QR 码固定为 1 比特（黑白二值）；这是 WIA-CODE 在结构上的容量优势所在。
  多级方案之所以可读，正是因为定位精度达到了亚像素级别。

## 实测结果（可复现——运行 `examples/benchmark.js`）

以下所有数据均由本目录中的参考代码生成，并非引用的外部数据。

**容量是可调节的旋钮**——灰度级越多，字节数越大；级数越少，鲁棒性越强。
每个码的净负载字节数（各档位默认纠错比例）：

| 网格 | 1比特（25% ECC） | 2比特稳健型（50% ECC） | 2比特最大容量型（35% ECC） | 3比特（50% ECC） |
|---|---|---|---|---|
| S（3728 单元格） | 344 | 458（×1.3） | 598（×1.7） | 690 |
| M（8848 单元格） | 824 | 1099 | 1432（×1.7） | 1646 |
| L（16016 单元格） | 1492 | 1994（×1.3） | 2590（×1.7） | 2994 |

QR 码被 ISO/IEC 18004 固定为 1 比特（黑白二值），无法跟进这一路线。

**与 QR 的鲁棒性对比**（相同负载、相同物理尺寸约 440px、相同劣化条件；QR 由 jsQR 解码，
WIA 由参考引擎解码——详见 `BENCHMARK.md`）。整体解码率（不含无劣化情形）：
**QR 75% · WIA-1比特 85% · WIA-2比特 80%**。

- **WIA 在透视方面完胜**——偏航角 0–50° 全部可解码；QR 在超过 40° 后失败。这正是
  AR 眼镜／手持斜角持握的典型场景。
- **WIA 在噪声方面胜出**（σ 30–60 区间 QR 已失效）——这是弱光／灾害现场的典型场景。
- **WIA-2比特在两个维度上同时领先 QR**：容量 ×1.3 **同时** 鲁棒性 80% 对 75%。
- 诚实地说也有劣势：WIA 的两种模式在**模糊**方面均落后于 QR（因为在同等尺寸下
  WIA-S 的模块更小），且 WIA-2比特在**极端低分辨率（缩放至 0.28×）**下也落后——
  灰度级别的读取需要足够像素，因此缩小/远距离的码应使用 1 比特模式。这种
  1比特↔多级方案的取舍正是容量与鲁棒性之间的调节旋钮，可根据实际条件按码选择
  （图书与屏幕场景 → 2–3 比特；灾害与远距离场景 → 1 比特）。

### 色彩（色相）层——附加容量，亮度信息完整保留

在灰度负载之上，第二个独立的负载搭载于**颜色**通道中。其原理（基于 YCbCr）是：色点的
亮度 Y 恰好等于灰度级别，因此 `toGray` 能够还原出与原始完全相同的亮度符号——**无论是
灰度扫描、黑白打印，还是色盲用户观看，基础负载都不会有任何丧失。** 色相在色度分量中
携带*额外*的比特。默认方案是**蓝黄（Cb）轴上的 K=2**——在 JPEG 压缩和打印场景下最为
稳健，且对色盲用户完全安全。实测数据（`examples/test-color.js`）：

| 模式 | S | M | L | 相对2比特亮度方案 |
|---|---|---|---|---|
| 2级亮度（无色相） | 458 | 1099 | 1994 | 1.00× |
| 2级亮度 + 1级色相 | 567 | 1369 | 2488 | **×1.25** |
| 2级亮度 + 2级色相 | 683 | 1644 | 2988 | ×1.50 |
| **3级亮度 + 2级色相** | 1029 | 2459 | **4474** | **×2.25** |

- 在常规扫描分辨率下**可承受 JPEG 4:2:0 色度子采样**（已实测，覆盖 M/L 网格，
  包含叠加模糊的情形）——这是任何彩色码都要面对的主要风险点。
- **诚实的边界说明**：色相的识读需要足够像素——这是一项近距离／截图／M–L 网格才适用
  的特性，在远距离/低分辨率下会最先失效。一旦色相失效，灰度基础层仍能完整解码
  （优雅降级）。两个色相平面各自独立进行纠错（RS 50%）。

## 使用方法

```bash
# Node — 数据往返测试（编码 → 渲染 → 劣化 → 检测 → 解码）
node examples/test-codec.js         # 1-bit
node examples/test-multilevel.js    # 2/3-bit grayscale capacity
node examples/benchmark.js --md     # regenerate BENCHMARK.md

# Browser — 免安装摄像头扫描器（通过 HTTPS 打开，并授予摄像头权限）
#   examples/scan.html + examples/wiascan-core.js  (self-contained, no CDN)
```

扫描引擎对外暴露的接口：
`WiaScan.detectAuto(imageData)` → `{ ok, text, hue, bitsPerCell, grid, shape, cellPx, corners, residPx, … }`
（自动识别缩放比例、网格、**形状**、级别与颜色）、`WiaScan.generate(opts)`（负载 → 生成码
PNG），以及 `WiaScan.renderTestCode(...)`。项目内附带一个浏览器端**生成器**
（`examples/generate.html`）和**扫描器**（`examples/scan.html`）。

## 形状与内容——QR 在结构上无法做到的事

- **形状**：`square`（方形）· **`round`（圆形）** · **`heart`（心形）**（任意轮廓都只是一层
  数据掩膜；检测过程本身基于径向对称，因而与形状无关——而 QR 的方形定位图案在结构上
  决定了 QR 不可能做成圆形）。扫描器会自动识别形状。在相同外接边界框下，圆形相对方形
  会损失约 24–28% 的容量，但在圆形物体（芯片、瓶盖、徽章）上*反而更有优势*，因为方形码
  必须内接于圆才能贴合。
- **内容类型／"配置即码"（config-to-code）**：文本、URL，以及结构化的 **SSH / API /
  MCP-bootstrap** 负载（紧凑 JSON 格式）——一份完整的服务器/API/智能体配置可以整个离线
  承载在一个码中。这正是 WIA 面向机器对机器场景的切入点：一种高容量、离线、无射频、
  抗透视畸变的标记方式，适用于 AI 智能体、机器人和气隙（air-gapped）环境的部署配置。
- **可嵌入视频**：由于检测过程对透视、旋转和运动的容忍度远高于 QR，将 WIA 码合成进
  动画/3D 视频后在实践中依然可读——在极端复合运动下并非每一帧都能解码，但实时扫描器
  只需要一帧成功即可，而 WIA 能捕获到的可用帧数远多于 QR（追求最大运动鲁棒性时应使用
  1 比特模式）。

## 参考实现（`reference/`）

纯 JavaScript 实现，可在 Node 与浏览器中运行，无外部依赖。

| 文件 | 作用 |
|---|---|
| `geometry.js` | 轨道几何规范 + 渲染器 + 数据单元格布局 |
| `frst.js` | Fast Radial Symmetry 检测器 + 亚像素/质心精化 |
| `conic.js` | 同心圆圆锥束（conic-pencil）透视恢复 |
| `locate.js` | 锚点定位 → 单元格→图像的单应性变换（`locateRobust`） |
| `codec.js` | 数据层：帧 + RS + 多级单元格 + 校准式分类 |
| `rs.js` | 独立实现的 Reed–Solomon（GF256）+ CRC-16 + 分块方案（无外部引擎） |
| `degrade.js` | 用于插桩劣化测试（仅供基准测试/单元测试使用） |
| `jsQR.js` | 第三方 QR 解码器，仅用于正面对比基准测试 |

## 诚实的现有技术与知识产权说明

同心圆机器可读码已有数十年的现有技术积累（MaxiCode 1992、ShotCode、TopCode，以及学术界
的圆形基准标记研究）；一项关键的同心环码专利（US 7,621,459）已于 2025 年到期，现属公有
领域。WIA-CODE 主张的创新性**仅限于**其具体的轨道锚点检测方法本身（FRST 定位 + 圆锥束
透视恢复 + 锚点校准式多级采样），而非"由圆形构成的码"这一概念本身。本项目以开源形式
发布，未申请任何专利；在提出任何商业主张之前，建议先进行正式的自由实施（freedom-to-
operate）审查。
